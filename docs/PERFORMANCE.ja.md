# 発熱・負荷対策

撮影画面を離れるか画面をロックすると録画を終了・保存します。[録画と権限](RECORDING.ja.md)。

[ガイド](README.ja.md) · [English](PERFORMANCE.md)

1.4.0のソースは **端末に合わせた推奨設定** で開始します。省メモリ端末・RAM不明・5 GiB未満・CPUが4コア以下のいずれかなら、写真921,600画素／動画VGAを目安にします。それ以外でRAMが8 GiB未満または8コア未満なら写真1,440,000画素／動画HD、それ以外なら写真・動画ともフルHDを上限の目安にします。動画は30fps以下を優先し、実際に対応するカメラ・エンコーダー出力から選びます。候補がなければ利用可能な出力に戻ります。CPU数は保守的な初期判定の材料であり、CPU速度やGPU性能の実測値ではありません。手動指定は保持します。

## 通常撮影とADVANCED MODE

初期OFFでは処理済み出力1枚を再利用し、選択したFAULTの全処理を維持します。シャッター処理時にGLスレッドで現在の処理画像を確保して保存します。最後に表示されたフレームとの厳密な一致は保証しません。通常動画も同じ処理出力を利用します。

ONでは従来の3枚の表示履歴を保持し、シャッター時に表示画像を確保します。切り替え時は古い出力を解放してカメラを再構成します。どちらも保存する画像とFAULT状態は確保後に変化しません。RAWは別露光のままです。通常経路は3枚のRGBA8履歴に比べ2枚分少なく、1920×1080なら約15.8 MiBの画素領域を節約します。これは理論上のバッファ量で、アプリ全体の実測メモリ・発熱・消費電力ではありません。1フレームあたりのFAULT処理量は変えていません。

設定 → **負荷と推奨設定** → **写真・動画を端末の推奨設定にする** で、推奨サイズと標準の動画品質へ戻せます。解像度の一覧でも推奨・手動・最大を選べます。この方針への最初の更新では従来の最大写真設定を推奨へ変更しますが、具体的なサイズの指定は保持します。更新後に最大を明示選択した場合は保持します。従来の動画サイズ未指定は推奨扱いです。JPGの選択サイズは保存サイズでもあり、使用中に更新回数を下げてもサイズは変えません。RAWは従来どおり別露光・対応するセンサー系FAULTを使います。

## LIGHT MODE — 未リリースの開発機能

設定 → モード → **LIGHT MODE**で、エフェクトのプレビュー処理を画面内の実表示画素数まで抑えます。縦横比を保ち、小さい入力は拡大しません。初期OFFで、ADVANCED／EXPERTが両方OFFの通常状態とは別のモードです。LIGHTをONにすると両方OFFになり、どちらかをONにするとLIGHTが解除されます。FAULTの保存値は維持します。

JPEG撮影時は、取得済みの最新入力を選択した保存解像度で一度処理し、画像を確保します。小さなプレビューの引き伸ばしではありません。細部や空間的なエフェクトはプレビューと保存画像で異なる場合があり、撮影フレームも最後の表示フレームとは限りません。撮影時のフル解像度処理が追加されるため、シャッター処理時間は延びる可能性があります。カメラ入力サイズは変えないため、GPU加工の削減であり、撮像系の消費電力低下を保証しません。

RGB録画中は元の解像度で処理し、停止後に小さなプレビューへ戻ります。動画の保存サイズ・記録周期は維持します。NETWORKは保持する処理画像を守るため、元の解像度で処理します。RAWは別のフル解像度センサー露光のままです。TIME ECHOの低解像度履歴入力も従来どおりです。ウィンドウを変更すると表示用サイズだけが追従します。既存の更新頻度・温度による自動制御はLIGHTでも有効です。

[実測と端末検証](audit/GPU_DETAIL_LIGHT.ja.md)はPixel 9での結果です。消費電力や長時間の発熱低下は未確認です。

## EXPERT MODE

設定 → モード → **EXPERT MODE**で、アプリ側の温度休止・負荷による上限・プレビューの時間間引きを解除します。写真は選んだサイズに対応する通常撮像の最大頻度を要求し、動画は選択したfpsを使います。実際の速度はカメラ・GPU・表示・撮影画像の保持枠に制約されます。解像度は保持するので、小さいサイズを手動指定するとさらに軽くできます。内部パラメータ表示・表示フレーム保持のADVANCEDとは独立し、切り替えるとその場で保存します。初期状態はOFFです。

EXPERTでは負荷対策用の温度取得を省き、アプリの温度基準による録画停止を行いません。OFFに戻すと自動調整へ戻ります。発熱と電池消費は増える場合があります。Androidや端末本体の温度保護、対応形式・画像保持枠・保存領域の確認は継続します。端末のオーバークロックやAndroidの制御解除を行う機能ではありません。

設定は「モード → 負荷と推奨設定 → 写真 → 通常動画 → RAW動画（実験的）→ 保存する情報 → アプリ」の順です。言語とプライバシー情報は「アプリ」にまとめています。

## 使用中の調整

EXPERTがOFFのとき、Androidの温度状態、取得できる場合の温度余裕予測（10秒より短い間隔では取得しない）、補助指標としてのバッテリー温度、描画にかかった時間、解像度とチェーン数を使います。この温度監視はLIVEやLIVEの温度入力がOFFでも動作します。選択したFAULTを変更したり、熱によるグリッチを作り足したりはしません。温度情報が取れない場合は不明として扱い、処理時間と保守的な負荷上限を使います。

プレビュー加工の上限は24fpsで、20・15・12・8・6fpsへ段階的に下げます。表示しないフレームではFAULTの組み立てと重い画像加工も省きますが、FAULTの時間は進み続けます。写真プレビューが遅くなった場合、対応するカメラでは撮像の要求も15fpsへ下げます。回復は余裕のある状態が15秒以上続いてから一段ずつ行います。カメラの配送が遅ければ、実際の更新頻度は画面の上限表示より低くなります。

通常録画は選択したサイズとエンコーダーの周期を維持し、録画するカメラ画像は引き続き加工します。表示更新を減らすだけでは録画加工の全負荷は下がらないため、動画では推奨解像度が主要な対策になります。録画の途中でサイズやコーデックを切り替えません。

AndroidがCRITICALの温度状態を返すか、バッテリー温度が48℃以上の場合は、録画を終了してカメラの連続撮像とLIVE入力を休止します。十分に温度が下がった状態が30秒以上続いてから再開します。ほかのバッテリー温度境界（40・42・45℃）や温度状態・余裕予測の境界は、アプリの負荷を抑えるための保守的な基準で、端末の安全温度を保証する数値ではありません。録画は自動で再開しません。

## 検証の範囲

端末を故意に加熱せず、温度情報を模擬した制御検証と実機カメラで確認します。Pixel 6 Proは接続されていないため、その機種での温度低下や長時間録画は別途確認が必要です。推奨サイズはカメラ・エンコーダーの対応範囲に依存し、温度APIの対応も端末によって異なります。[Androidの温度に応じた負荷調整の案内](https://developer.android.com/games/optimize/adpf/thermal)を参考に、処理時間とバッテリー情報も組み合わせています。
