# 実験的な端末連動

[ガイド一覧](README.ja.md) · [English](EXPERIMENTAL_SIGNALS.md)

開発ブランチの機能で、公開済み1.3.0には含まれません。設定の「実験的な端末連動」で、FAULTごとの入力感度と、MOTION BLUR・THERMAL NOISE・SMEARの3種類の撮像現象をまとめて有効にします。初期値はOFFで、切替は即時保存されます。OFFに戻すと調整値と選択を保持したまま追加機能の作用を止めます。従来の13 FAULTは引き続き使えます。

ADVANCED MODEを有効にし、チェーン内の項目を開いて「端末入力」を選びます。動き・音・フレーム時間・温度・アプリCPUを、それぞれ0〜4の感度で調整できます。0はその項目への入力を切断、1は標準の倍率です。AUTOは元の接続に戻し、接続済みの入力は1、未接続は0になります。FIX・数値入力・スライダーはFAULT編集画面の適用／キャンセルに従います。未接続の入力を加えると項目の強度が増しますが、物理量を校正した関係ではありません。

端末入力への反応はLIVE ON時に働き、全体の入力スイッチと権限が優先されます。LIVEの一時停止中は状態を保持します。描画値のFIXや撮像現象の最低量を設定すると、測定値がなくても一定の効果を作れます。感度0はその入力の寄与を止める操作で、FAULT本来の模様や時間変化を消す操作ではありません。

| 撮像現象 | 表現モデル | RAW処理 |
|---|---|---|
| MOTION BLUR | ジャイロの角速度や動きと露光時間からブレを作る。方向と最低量は表現用の調整値 | 同じBayer位相の9点を参照 |
| THERMAL NOISE | 温度と露光時間に応じて粒状ノイズの強さを変える | 範囲内に収めたサンプル雑音 |
| SMEAR | 明部を縦に広げ、読み出し時間に応じて強さを変える | 同じBayer位相の8点を参照 |

順序はMOTION BLUR → THERMAL NOISE → PIXEL DAMAGE → EXPOSURE → SMEAR → 従来の残りのFAULTです。追加の3種類は撮像現象として扱います。光学系の校正、実CCDの電荷転送、前フレームの蓄積を再現するものではなく、表現用の近似です。温度には既存のバッテリー温度・Androidの熱状態を使い、撮像素子の温度を直接測定しません。アプリCPUはアプリ自身の処理活動で、端末全体のCPU使用率ではありません。

プレビュー・JPEG・通常動画はRGB処理を使います。加工RAW写真では従来の6種類に加え、3種類の撮像現象をBayerサンプルへ適用できます。カメラRGBとRAWは異なる表現なので、結果の完全一致は想定しません。オリジナルRAWとオリジナルRAW動画ZIPは無加工です。加工した撮影結果には、その時点の確定値と実験機能の有効状態を保持します。

ブレとスミアは画素ごとに複数の周辺点を参照するため、処理負荷が増える場合があります。既存の発熱・負荷対策は従来の設定に従います。このスイッチでEXPERT MODEは有効になりません。

エミュレーターでは3種類のGPU描画と再現性、OFF時の停止、感度編集の適用・キャンセル・保存、表示JPEGとメタデータの整合性を確認しました。単体検証では入力の分離、OFF時の既存出力、RAW値の範囲とBayer位相、複製・一時停止、保存値の互換性を確認しています。実機でも同じUI・GPU・JPEGの検証が通りました。3種類とROW ERRORを重ねた4096×3072の加工DNGはLibRawで読み込み・展開・現像でき、説明情報に3項目と`experimental=true`が含まれています。実験機能OFF／ONの各約20秒の無音MP4は、1080×1920・30.05fpsで時刻情報と全フレームの復号が正常でした。

初回のRAW検証では40秒の待機制限を超えました。ブレとスミアの参照座標を事前計算する修正後、直接計算と同じ出力であることを回帰テストで確認し、同じ解像度を開発ビルドで約17秒で保存できました。高画素の加工RAWには引き続き時間がかかります。USB接続時のバッテリー温度はOFF動画で35.9℃、ON動画で35.9〜36.4℃でした。短時間・順次実行の記録なので、機能だけの発熱差や長時間の温度を示すものではありません。[検証記録](audit/experimental-signals-results.json)。
