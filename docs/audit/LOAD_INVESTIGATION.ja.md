# 描画とRAW処理の負荷調査 — 2026-09-10

[詳細・測定方法](LOAD_INVESTIGATION.md) · [測定値](load-investigation-results.json) · [棚卸し](README.ja.md)

Pixel 9のDEV版で比較しました。アプリ本体は変更せず、試作と測定はテスト側だけです。

| 優先度 | 結果 |
|---|---|
| RAWの粒状ノイズ計算をセル単位で再利用 | 粒サイズ8では240.87→149.43ms、約38%短縮。全画素一致。粒サイズ1では差が小さい。加工RAW限定の改善候補 |
| MEDIA／DISPLAYの最終転送を条件付きで省略 | LEDの1080p処理は2回とも約9～15%短縮し、比較画像は全バイト一致。DVD→CRTは改善と悪化が混在、Analog→LEDは1080pで改善せず。一律適用しない |
| RAW処理に固定の休止を挟む | 約1200万画素・6段RAW処理が2.57～2.93秒から4.52～4.61秒へ延長。プレビューは両方約59fps。今回の端末では採用する根拠がない |

最終の1080p GPU測定では、通常13段が約8.73ms、CFA ERRORが約3.09ms、DEMOSAIC ERRORが約2.61msでした。CPU側の約200万画素RAWでは、SMEAR約476ms、MOTION BLUR約336ms、THERMAL NOISE約239msが重い処理でした。GPUとCPUの値は別経路なので直接比較しません。

合成RAWのDNG生成は書き捨て先で18～32ms、一時ファイルで67～70ms。撮影・MediaStore公開・サムネイル・永続化保証を含まず、実際の撮影から保存までの時間ではありません。

USB給電、固定クロックなし。GPUの再測定では温度状態が変わったため、測定間の単純比較には限界があります。最初のGPU測定で無効だった実験エフェクト3件はJSONに除外を明記し、有効化して再測定しました。低性能実機、消費電力、長時間の表面温度、表示遅延・シャッター遅延の分位値は未測定です。

次はセルキャッシュの境界条件とLEDの直接出力を追加検証するのが妥当です。固定の休止は導入せず、プレビューの処理期限に遅れる端末で必要性を確認してから検討します。
