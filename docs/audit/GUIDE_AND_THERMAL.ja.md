# 操作ガイド・設定保存・発熱の調査

[English](GUIDE_AND_THERMAL.md) · [測定データ](guide-thermal-results.json) · [データ注入の検討](DATA_INJECTION_POINTS.ja.md)

開発ブランチ：`codex/interactive-guide-thermal-inputs`。公開済みリリースと提出済みバンドルは維持。

## 変更内容

- 実際の操作部をハイライトする8段階のガイドへ変更。練習用信号をタップ・LEVEL操作で変えられる。撮影や設定変更は起こさず、常時アニメーションも使わない。
- ガイド中はカメラ処理、表示確認の定期処理、位置情報取得を止める。終了後はカメラへ復帰する。設定画面から開く場合は設定を一時的に隠し、実際の操作部を見せる。
- 追加依頼に合わせ、設定は選択時に即保存する方式へ変更。「適用」は廃止。閉じる・再作成・ガイド表示後も選択を保持する。言語とADVANCEDだけの変更ではカメラを再設定しない。
- 「推奨設定を使用」でEXPERTもOFFにする。従来は解像度等を変更してもEXPERTが残り、自動負荷調整が効かない状態だった。
- 短時間に連続して設定を選ぶ場合、古いカメラ設定要求を飛ばし、古い設定の保存で新しい選択を上書きしないようにした。FAULT・LIVE編集の適用／取消は従来どおり。

## 分かったこと

実機は最大3072×4096の信号解像度＋EXPERTだった。この解像度は1080×1920の約6倍の画素数／フレームで、FAULTの数だけ処理が増える。EXPERTは仕様としてアプリの自動負荷調整・温度休止を外す。既存のユーザー選択を自動的に書き換えたり、エフェクトの品質を落としたりはしていない。

従来の説明画面は、裏でカメラ処理を続けていた。PIXEL DAMAGE／ROW ERROR／VHS、LEVEL .55、LIVE OFFの短時間測定では、ガイド中の処理は以下になった。

| | 修正前 | 修正後 |
| --- | ---: | ---: |
| 測定時間 | 12秒 | 12.059秒 |
| 処理したフレーム | 359 | **0** |
| プロセスのCPU時間 | 5410 ms | **166 ms** |
| CPU使用率（1コア換算） | 45.08% | **1.38%** |

**ガイド中の不要な処理は削減できた。端末全体の消費電力や表面温度が何度下がるかを測った結果ではない。**

1.1.0との同じ公称設定の比較も行ったが、推奨設定の実フレームレートが揃わず、CPU値も変動した。最大／EXPERTは両方とも約30 fps。短時間の逐次測定から「新版が全般に熱くなった原因」を断定することはできない。

Android 16／Mali-G925の1台、AC給電中。電池温度表示は約37.5〜37.8℃、温度状態は0。表面温度計・電力計・同じ開始温度からの長時間比較は未実施。タイムアウトした測定と、途中で画面切り替えが入った60秒測定は除外した。採用した修正後の測定では100 msごとにアプリとガイドの表示継続を確認した。通常撮影を長時間続けた場合の発熱差は、この測定では未確定。

## 検証

実機で全8ページ×日本語・英語・中国語、ハイライト位置、カメラ停止、練習による撮影状態の非変更、ページ復元、スキップ／戻る／完了、設定からの再表示、終了後のカメラ復帰を確認。24枚の画面を確認した。追加の即時保存方式もエミュレーターのガイド検証に成功。1080×1920・文字倍率1.5のエミュレーターで確認。`settings-auto`でJPEGの選択時保存・連続切り替え・再起動／再表示、`expert`で即保存・録画／通常の温度保護復帰、`capture-contract`で表示JPEGの画素一致とメタデータを確認。単体テスト12件、Kotlin／Androidテストのビルド、lint、416文字列の翻訳整合性、リポジトリ検査に成功。

シェーダー・RAW処理の数式は変更していない。データ注入は別レポートに可能な位置と実装条件を整理し、機能自体は追加していない。

カメラ権限を拒否した状態でもガイドを先に表示でき、終了後にだけ権限を求める検証にも成功。
