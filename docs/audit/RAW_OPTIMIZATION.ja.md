`codex/kotlin-cleanup` の未リリース変更です。PIXEL DAMAGEとROW ERRORのCPU側RAW処理を対象に、設定取得と列・行で共通の計算をまとめました。

乱数の種・座標、浮動小数点の演算順、丸め・クリップ、Bayer配列を維持する移動量、変更前の入力から読み込む規則は維持しています。画像コピーやエフェクトの順序、シェーダー、撮影・保存処理は変更していません。

最適化前の実装をテスト専用の比較基準として保存し、種・LEVEL・LIVE・組合せ・画像寸法・黒白レベルを変えた600条件で全バイトの一致を検証しました。入力を変更しないことも確認しています。既存のJava版由来の固定出力ハッシュも変更せず通過しました。全入力の網羅検証ではありません。

ユニットテスト10件、debugビルド、静的チェックが通過しました。静的チェックはエラー0、既存の警告136件とヒント1件です。

## 実機測定

25060RK16C / Android 16、F-Droid debug版。最適化前→後→後→前→前→後の順で各3回測定しました。固定1920×1080 RAW16データにPIXEL DAMAGE + ROW ERRORを適用し、各回10回の準備後に30回測定しています。撮影・ファイル保存は含みません。

| 実行 | RAW処理時間の中央値（ms） |
|---|---:|
| before-1 | 843.71 |
| after-2 | 195.17 |
| after-3 | 196.05 |
| before-4 | 845.52 |
| before-5 | 851.78 |

各3回の中央値は **845.52ms → 195.17ms**。今回の条件では **4.33倍、処理時間76.9%短縮**です。全6回でRAW出力のSHA-256が従来の値と一致しました。

バッテリー温度は38.0〜38.4℃、OSの温度制限状態は[0]（0は制限報告なし）でした。電源接続状態で測定し、CPU周波数は固定していません。単一端末・debug版・特定の合成データによる短時間測定であり、全エフェクトや撮影全体で同じ倍率になるという意味ではありません。RAWのピークメモリは未測定です。列情報の保存に画像幅分のBooleanArrayとIntArrayを追加しています。
