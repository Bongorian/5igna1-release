# FAULTシステム再設計

基準は公開release版 `7dd83a7`（1.0.0）。[詳細な設計・現状との差分・検証条件（English）](FAULT_SYSTEM.md)。

中心は「同じ壊れた系の性格を保ちながら、その時にしか現れない事故を撮る」ことです。実カメラ由来の信号だけを扱い、意味推論による被写体の生成・補完はしません。

現行の共通4値、AUTOによるseedを含む全パラメータ補間、Chain自動切替を廃止します。13 FAULTを8 FAULT POINTに整理し、各FAULTは項目数が異なる名前付き操作値と個体seedを持ちます。操作値から、制約のない故障機構パラメータへ変換します。IDENTITY、連続したMOTION、突発的なEVENTを独立させます。通常の時間進行で個体や選択経路を変えません。RESEEDは選択中の故障個体だけを変えます。

既存の端末入力取得・Camera2制御・不変設定・編集の適用／キャンセル・保存・RAW記録キューは再利用します。LIVEは端末状態の結合です。固有の時間変化は各FAULT自身が持ちます。VHS/CRTの媒体・表示特性と、その中の故障は別パラメータです。STREAM ERRORは復号済み画像領域の欠落／同一フレーム内のサンプル再利用をモデル化し、実packetの破壊を装いません。

通常JPEGは最後に表示した処理済みカメラフレームを保存します。表示・動画は同じ処理画像を参照します。JPEGの解像度は実プレビュー信号の解像度になります。フル解像度の後続露光を再加工して同じ瞬間と呼ぶことはしません。録画中はドラフト編集を開始できず、適用済み設定を表示・記録します。

RAWは異なる表現・別露光であり、RGBプレビューそのものではありません。加工RAWはラッチした同じFAULT状態を使い、原本RAWは無加工で保存します。原本RAW動画の有界キューは維持します。内部にはFAULT POINTで終わる経路prefixを表す記録tapを用意し、途中信号の保存を拡張できる形にします。

旧FAULT設定のみ新スキーマで初期化し、撮影設定・言語・位置情報は保持します。アプリIDや公開バージョンは変更せず、公開操作は行いません。
