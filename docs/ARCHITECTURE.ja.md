# 内部設計

[English](ARCHITECTURE.md) · [現状調査と移行設計](design/FAULT_SYSTEM.ja.md)

アプリ本体とテストはKotlin、GPU処理はGLSLです。`CameraScreen`が画面構築と操作の結び付け、`MainActivity`がライフサイクルと操作の調整を担当します。`CaptureStorage`が完成した撮影データを保存し、カメラとGLの資源は`GlitchEngine`が所有します。スナップショットのコレクションは防御的コピーを取り、Java経由の変更も拒否します。既存のAndroid Viewと標準カメラAPIを利用します。

Effectsが基本13 FAULTと任意の実験的3段階・8地点・操作項目・適用順・RAW対応を管理します。EffectParametersはFAULTごとに項目数が異なる名前付き操作値と64bit個体seedを保持します。EffectStateは不変の選択経路です。LEVELを各故障機構へ変換し、共通strengthの物理制約を設けません。

FaultModelはカメラフレームごとに一度だけ時間を進めます。FaultNodeにIDENTITY・MOTION・EVENTと名前付き機構パラメータを固定し、読み取りで再抽選しません。構造・drift・事故の乱数領域は独立しています。LIVEは既存の端末入力取得を結合するだけで、固有の時間変化は各FAULT自身が持ちます。

GlitchEngineは実ソース解像度で一度処理し、表示とエンコーダーに同じSignalBufferを渡します。ADVANCED OFFではencoderScratchの1枚を再利用し、GLスレッドのシャッター処理で画像を確保します。表示履歴は保持しません。ADVANCED ONではFrameHistoryの3枠で表示待ち／表示済み画像を保持し、TextureViewが受け取った表示時刻tokenを確認し、対応する元のcamera timestampを保持します。カメラとEGLの時計の一致は仮定しません。シャッターはGLキューに送る前に対象枠を予約するため、後続フレームが上書きできません。画面が遅れる場合は表示更新を待ち、録画用scratchは独立して同じ時間進行を記録できます。

JPEGは通常出力またはADVANCEDで予約した画像を読み出して保存し、EXIFへ時刻・FAULT状態を記録します。別露光の再処理はしません。設定は変更時に即保存し、撮影経路の変更はカメラを再構成します。FAULT・LIVE編集はドラフト／適用／キャンセルを維持し、録画中のドラフト開始を防ぎます。画面のシャッター・音量キーとも、FAULTまたはLIVEの編集を適用・破棄してから撮影します。

RawGlitchは同じFaultNodeのRAW16アダプターです。DNGは別露光であり、RGBプレビューと同一とはしません。原本RAW動画の有界キューや保存処理は維持します。Frame.through(Point)で途中信号記録のための因果順prefixを表します。

旧FAULT設定だけを新スキーマへ初期化し、撮影設定・言語・位置情報・アプリIDは保持します。全コア機能をsrc/mainに置きます。[検証](VALIDATION.md)

## 撮影画面と共通プレビュー

`SignalSheet.anchoredPick`は形式選択をボタン直下に配置します。ライト・GPS・動画音声を上部にまとめ、音声は写真モードでも表示します。`FaultStateDialog`は表示位置を保ったメーター行に発生量を更新し、カメラプレビューの下に専用領域を確保します。

`MediaPreview`は撮影フォルダー内の読み取れる写真・動画を共通の一覧にします。写真は単一ワーカーで長辺2048ピクセル以内に読み込み、DNGは端末のサムネイルを使います。MediaPlayerとSurfaceは現在の動画だけが所有します。GLキューでカメラの解放完了を待ってから動画を準備します。閉じるときは再生・音声フォーカス・保留中のUI更新を解放してカメラを再接続し、遅れて届く処理結果は世代番号で除外します。バックグラウンド移行時も閉じます。外部閲覧は明示操作で別タスクに開きます。

表示確認が6秒間進まない場合、撮影中と冷却休止中を除き、最大3回カメラを再接続します。カメラ切断・エラーも同じ復帰経路を使い、バックグラウンド移行で再試行を取り消します。撮影設定と選択中の効果を保持します。

実験的な端末連動がONなら、加工RAWでもブレ・熱雑音・スミアを追加できます。対応範囲と近似の制限は[実験機能](EXPERIMENTAL_SIGNALS.ja.md)を参照してください。

`MainActivity.onPause`は非表示状態を記録し、写真処理を待機させ、GLスレッドで`close()`を実行します。カメラの解放処理はレコーダーとGL資源の破棄前に`stopVideo()`を呼びます。MP4は終了・公開し、RAWは新規受付を止め、上限付きの保存キューを処理してZIPを公開します。フォアグラウンドサービス、起動保持、バックグラウンド描画用Surfaceはありません。復帰時はプレビューを接続し直し、録画は再開しません。


カメラ選択は、公開カメラIDと論理カメラが公開する物理IDを列挙します。物理センサーは親の論理カメラを開き、プレビュー・静止画・RAW出力を同じ物理IDへ接続します。選択ごとに解像度・RAW能力を管理し、露出などは選択センサーの撮影結果を使います。一致する撮影結果がなければ別センサーの情報で埋めません。保存済みメディアの「この設定を使う」はカメラ選択を変更しません。

デジタルズーム操作と旧倍率の復元を削除し、要求倍率を1.0、クロップ領域を全有効画素に固定します。対応する物理クロップ制御は、そのセンサーの座標系を使います。光学調整は、制御キーが使える場合に限り、端末が公開する有効な焦点距離だけを要求します。論理カメラの焦点距離一覧を、無段階の光学ズーム対応とは解釈しません。
